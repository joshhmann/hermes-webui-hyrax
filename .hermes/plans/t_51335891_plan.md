# TDD Plan: Deep-dispose Tai Loft resources and async races

## Audit findings

### Current mountTaiLoft cleanup gaps
- Returned cleanup calls `room.destroy()` + `workbench.destroy()` + removes keydown listener
- **Missing**: shell DOM not removed from host, button click listeners never cleaned up (browser GC handles child-element listeners, but explicit cleanup is safer)

### Current TaiRoomScene.destroy() gaps
Only does: `cancelAnimationFrame`, `resizeObserver.disconnect()`, `controls.dispose()`, `skeletonHelper?.removeFromParent()`, `renderer.dispose()`, `renderer.domElement.remove()`

**Not disposed:**
- Scene objects (all meshes/materials/geometries/lights from seedRoom) — 100+ THREE resources leak
- `this.objects` Map never cleared
- `this.rig` (AvatarRig) — AnimationMixer, boneCache, localBindCache, desiredRetargetPose all leak
- `this.locomotion` (ProceduralLocomotion) — bindPositions WeakMap + state
- `this.face` (FaceController) — GazeSystem state
- `this.visemes` (VisemeController) — queue
- `this.timeOfDay` (TimeOfDaySystem) — light references
- `this.navigation` (RoomNavigation) — obstacles array
- `this.clock` — no-op (stateless)

### Subsystem dispose gaps
- AvatarRig: no dispose() -> mixer.stopAllAction(), clear caches
- ProceduralLocomotion, FaceController, GazeSystem, VisemeController, TimeOfDaySystem, RoomNavigation: no dispose() at all
- RigDevelopmentPanel: has destroy() but doesn't remove button/input listeners inside workbench

### Missing guards
- Late load success/failure after dispose -> no guard exists
- 20 mount cycles -> canvases/listeners accumulate
- webglcontextlost/restored -> no handling
- Reduced motion -> CSS media query only, no programmatic check
